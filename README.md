# Стандарт фронтенда

Версия **1.0.1**. Для клиентских веб-приложений с отдельным backend.

Репозиторий содержит три самостоятельные части:

| Часть | Точка входа | Назначение |
|---|---|---|
| Стандарт | [standard/frontend.md](standard/frontend.md) | Требования к реализации и рекомендуемые технологии |
| Skill | [skills/frontend-standard/SKILL.md](skills/frontend-standard/SKILL.md) | Работа агента: новый проект, аудит, модернизация |
| Пайплайн использования | [pipeline.md](pipeline.md) | Подключение, установка, команды пользователя и результаты |
| Инструкции этого репозитория | [AGENTS.md](AGENTS.md) | Как поддерживать стандарт и skill |
| Инструкции прикладного проекта | [templates/AGENTS.frontend.md](templates/AGENTS.frontend.md) | Блок для добавления в существующий AGENTS.md |

## Структура

```text
standard/
  VERSION                   # Версия переносимого стандарта
  frontend.md               # Архитектура, данные, UI и темы, проверки и выпуск
skills/frontend-standard/
  SKILL.md                  # Три режима работы агента
  agents/openai.yaml        # Метаданные для Codex
templates/
  AGENTS.frontend.md        # Постоянные инструкции целевого проекта
  adoption.md               # Принятая версия и проектные решения
  audit.md                  # Доказательный аудит и приоритеты
  modernization.md          # План, выполнение и приёмка
pipeline.md                 # Как применять всё вместе
AGENTS.md                   # Инструкции для сопровождения этого репозитория
```

Стандарт можно использовать без skill и без Codex. Skill задаёт процедуру применения; требования живут в `standard/`. Пресеты, продуктовые палитры, конкретные шрифты и приватные зависимости не навязываются.

## Начало работы

1. Прочитать [пайплайн](pipeline.md) и подключить выбранную редакцию к проекту.
2. Добавить блок из шаблона в его `AGENTS.md`.
3. Установить skill по инструкции либо передать агенту путь к исходному `SKILL.md`.
4. Попросить подготовить новый проект, провести аудит или выполнить согласованный объём модернизации.

Пример после установки:

> Используй $frontend-standard. Проведи аудит фронтенда текущего репозитория по закреплённой версии стандарта. Подготовь доказательный отчёт и план модернизации. Исходный код пока не меняй.

Обновление этого репозитория не обновляет требования прикладных проектов автоматически. Каждый проект хранит выбранную редакцию и принимает переход явно.

## Версии

Версия хранится в `standard/VERSION`. Git-тег `v1.0.1` обозначает текущую редакцию: механизм тем включён в единый стандарт. Требования сохранены; первоначальный выпуск `v1.0.0` остаётся в истории. Изменение обязательных требований выпускается новой версией; несовместимое изменение повышает major, дополнение — minor, редакционная правка без изменения требований — patch. Опубликованные теги не перемещаются.

В проект переносится содержимое `standard/` без редактирования. Особенности, исключения и принятые альтернативы записываются в `adoption.md` рядом с копией. Достаточно версии и ссылки на выпуск; собственные хэши и реестры контрактов не нужны.

Основа документа — обобщённый опыт AI Lead Monitor и изучение механизма тем FOT. История этих проектов и их незавершённые миграции не являются требованиями стандарта.
