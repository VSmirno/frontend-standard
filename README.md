# Стандарт фронтенда

Версия **1.0.3**. Для клиентских веб-приложений с отдельным backend.

Репозиторий содержит три самостоятельные части:

| Часть | Точка входа | Назначение |
|---|---|---|
| Стандарт | [standard/frontend.md](standard/frontend.md) | Требования к реализации и рекомендуемые технологии |
| Skill | [skills/frontend-standard/SKILL.md](skills/frontend-standard/SKILL.md) | Работа агента: новый проект, аудит, модернизация |
| Пайплайн использования | [pipeline.md](pipeline.md) | Подключение, установка, команды пользователя и результаты |
| Инструкции этого репозитория | [AGENTS.md](AGENTS.md) | Как поддерживать стандарт и skill |
| Инструкции прикладного проекта | [templates/AGENTS.frontend.md](templates/AGENTS.frontend.md) | Блок для добавления в существующий AGENTS.md |

## Структура

```text
standard/
  VERSION                   # Версия переносимого стандарта
  frontend.md               # Архитектура, данные, UI и темы, проверки и выпуск
skills/frontend-standard/
  SKILL.md                  # Три режима работы агента
  agents/openai.yaml        # Метаданные для Codex
templates/
  AGENTS.frontend.md        # Постоянные инструкции целевого проекта
  adoption.md               # Принятая версия и проектные решения
  audit.md                  # Доказательный аудит и приоритеты
  modernization.md          # План, выполнение и приёмка
pipeline.md                 # Как применять всё вместе
AGENTS.md                   # Инструкции для сопровождения этого репозитория
```

Стандарт можно использовать без skill и без Codex. Skill задаёт процедуру применения; требования живут в `standard/`. Пресеты, продуктовые палитры, конкретные шрифты и приватные зависимости не навязываются.

## Установка и обновление через чат Codex

Пользователю достаточно отправить агенту:

> Репозиторий: ssh://git@gl.rnd.lanit.ru:2222/DEV/standards/frontend.git. Прочитай README, установи или обнови и переустанови skill frontend-standard для моего пользователя по инструкции. Всё выполни сам; мне не нужно запускать команды или копировать файлы.

Агент получает репозиторий, читает инструкции ниже и устанавливает полный пакет. Python, installer-скрипты и ручные действия пользователя не требуются. Если доступ к GitLab отсутствует, агент сообщает конкретную ошибку и необходимое действие, не запрашивая секреты в чате.

### Инструкция агенту: установка / обновление / переустановка

1. Используй разрешённый пользователем remote. Получи актуальную `main` через Git; если пользователь указал выпуск, используй его. Проверь remote, ветку и SHA. Существующий грязный checkout не сбрасывай: используй отдельную временную копию. Читай инструкции из выбранного снимка.
2. По умолчанию устанавливай для пользователя: `$CODEX_HOME/skills/frontend-standard`, при отсутствии CODEX_HOME — `~/.codex/skills/frontend-standard`. Только по явному запросу установки в проект используй `<project>/.agents/skills/frontend-standard`. Определи абсолютный путь и проверь, нет ли проектной копии, способной перекрыть пользовательскую. Другие копии автоматически не меняй, но сообщи о них.
3. Подготовь полный пакет во временном каталоге вне сканируемой папки skills. Используй обычные файловые операции доступными инструментами агента. Не запускай installer-скрипты и не проси пользователя копировать ресурсы. Состав:
   - `skills/frontend-standard/SKILL.md` → `SKILL.md`;
   - `skills/frontend-standard/agents/` → `agents/`;
   - `standard/` → `references/standard/`;
   - `templates/` → `references/templates/`;
   - `pipeline.md` → `references/pipeline.md`;
   - `README.md` → `references/README.md` для будущего обновления.
4. До замены проверь наличие SKILL.md, frontmatter с name/description, метаданных agents, версии, единого стандарта, шаблонов и pipeline. Проверь ссылки рабочего пакета; ссылки README на исходную структуру репозитория являются справочными.
5. Если назначение уже существует, прочитай его версию и состав. Сохрани **весь** прежний каталог в резервную копию вне папок обнаружения skills, например `$CODEX_HOME/skill-backups/frontend-standard/<дата-время>/`. Для проектной установки резервную копию также можно хранить в пользовательском каталоге. Не удаляй и не перезаписывай предыдущие резервные копии. Сначала проверь разрешённые абсолютные пути. При symlink/junction сначала выясни его назначение; не следуй по нему для перезаписи другого каталога.
6. Замени назначение подготовленным пакетом целиком, чтобы старые ресурсы не оставались рядом с новыми. Если замена не удалась, восстанови прежнюю установку из резервной копии. Разрешение пользователя обновить/переустановить skill достаточно для этих локальных действий; повторного подтверждения обычного копирования не требуется.
7. Проверь конечный состав и совпадение файлов с выбранным Git-снимком. В коротком отчёте укажи версию, SHA, путь установки и путь резервной копии, если она создана. Не объявляй skill автоматически загруженным: предложи вызвать `$frontend-standard` на следующем ходе; если клиент не подхватил установку, открыть новую сессию.
8. Установка skill не изменяет код, AGENTS.md и закреплённые стандарты прикладных проектов. Подключение или обновление принятой проектом версии выполняется отдельным поручением.

Самодостаточная установленная папка:

```text
frontend-standard/
  SKILL.md
  agents/openai.yaml
  references/
    standard/{VERSION,frontend.md}
    templates/{AGENTS.frontend.md,adoption.md,audit.md,modernization.md}
    pipeline.md
    README.md
```

### Использование после установки

Для подключения к открытому проекту:

> Используй $frontend-standard. Подключи стандарт к этому репозиторию и закрепи его в AGENTS.md. Код приложения пока не меняй.

Для аудита:

> Используй $frontend-standard. Проведи аудит по закреплённой версии стандарта и подготовь план модернизации. Исходный код пока не меняй.

Для выполнения плана:

> Используй $frontend-standard. Выполни согласованный план модернизации, проверь результат и исправь недоделанное.

Подробный порядок и результаты каждого режима описаны в [pipeline.md](pipeline.md). Обновление skill не обновляет автоматически требования прикладных проектов.

## Версии

Версия хранится в `standard/VERSION`. Git-тег `v1.0.3` обозначает выпуск с установкой и переустановкой агентом по запросу в чате. Механизм тем включён в единый стандарт. Требования сохранены; первоначальный выпуск `v1.0.0` остаётся в истории. Изменение обязательных требований выпускается новой версией; несовместимое изменение повышает major, дополнение — minor, редакционная правка без изменения требований — patch. Опубликованные теги не перемещаются.

В проект переносится содержимое `standard/` без редактирования. Особенности, исключения и принятые альтернативы записываются в `adoption.md` рядом с копией. Достаточно версии и ссылки на выпуск; собственные хэши и реестры контрактов не нужны.

Основа документа — обобщённый опыт AI Lead Monitor и изучение механизма тем FOT. История этих проектов и их незавершённые миграции не являются требованиями стандарта.
