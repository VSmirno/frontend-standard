# Установка и обновление frontend-standard: инструкция агенту

Прочитай этот документ, если пользователь поручил установить, обновить или переустановить skill `frontend-standard`. Выполни получение репозитория, сборку пакета, резервное копирование и проверку самостоятельно. Готовить файлы или запускать установщик пользователю не нужно.

Используй URL репозитория, указанный пользователем. Инструкция одинаково применяется к GitHub и другим Git-хостингам. Если доступа нет, сообщи конкретную ошибку и необходимое действие; не запрашивай секреты в чате.

## Порядок установки

1. Используй разрешённый пользователем remote. Получи актуальную `main` через Git; если пользователь указал выпуск, используй его. Проверь remote, ветку и SHA. Существующий грязный checkout не сбрасывай: используй отдельную временную копию. Читай инструкции из выбранного снимка.
2. По умолчанию устанавливай для пользователя: `$CODEX_HOME/skills/frontend-standard`, при отсутствии CODEX_HOME — `~/.codex/skills/frontend-standard`. Только по явному запросу установки в проект используй `<project>/.agents/skills/frontend-standard`. Определи абсолютный путь и проверь, нет ли проектной копии, способной перекрыть пользовательскую. Другие копии автоматически не меняй, но сообщи о них.
3. Подготовь полный пакет во временном каталоге вне сканируемой папки skills. Используй обычные файловые операции доступными инструментами агента. Не запускай installer-скрипты и не проси пользователя копировать ресурсы. Состав:
   - `skills/frontend-standard/SKILL.md` → `SKILL.md`;
   - `skills/frontend-standard/agents/` → `agents/`;
   - `standard/` → `references/standard/`;
   - `templates/` → `references/templates/`;
   - `pipeline.md` → `references/pipeline.md`;
   - `README.md` → `references/README.md`;
   - `INSTALL.md` → `references/INSTALL.md` для будущего обновления.
4. До замены проверь наличие SKILL.md, frontmatter с name/description, метаданных agents, версии, единого стандарта, шаблонов, pipeline и этой инструкции INSTALL.md. Проверь ссылки рабочего пакета; ссылки README на исходную структуру репозитория являются справочными.
5. Если назначение уже существует, прочитай его версию и состав. Сохрани **весь** прежний каталог в резервную копию вне папок обнаружения skills, например `$CODEX_HOME/skill-backups/frontend-standard/<дата-время>/`. Для проектной установки резервную копию также можно хранить в пользовательском каталоге. Не удаляй и не перезаписывай предыдущие резервные копии. Сначала проверь разрешённые абсолютные пути. При symlink/junction сначала выясни его назначение; не следуй по нему для перезаписи другого каталога.
6. Замени назначение подготовленным пакетом целиком, чтобы старые ресурсы не оставались рядом с новыми. Если замена не удалась, восстанови прежнюю установку из резервной копии. Разрешение пользователя обновить/переустановить skill достаточно для этих локальных действий; повторного подтверждения обычного копирования не требуется.
7. Проверь конечный состав и совпадение файлов с выбранным Git-снимком. В коротком отчёте укажи версию, SHA, путь установки и путь резервной копии, если она создана. Не объявляй skill автоматически загруженным: предложи вызвать `$frontend-standard` на следующем ходе; если клиент не подхватил установку, открыть новую сессию.
8. Установка skill не изменяет код, AGENTS.md и закреплённые стандарты прикладных проектов. Подключение или обновление принятой проектом версии выполняется отдельным поручением.

Самодостаточная установленная папка:

```text
frontend-standard/
  SKILL.md
  agents/openai.yaml
  references/
    standard/{VERSION,frontend.md}
    templates/{AGENTS.frontend.md,adoption.md,audit.md,modernization.md}
    pipeline.md
    README.md
    INSTALL.md
```

## После установки

Установка делает skill доступным агенту, но не подключает стандарт к прикладному проекту. Дальнейшая задача определяется запросом пользователя: закрепление стандарта, новый проект, аудит или модернизация. Примеры команд приведены в [README](README.md), порядок применения — в [pipeline](pipeline.md).
