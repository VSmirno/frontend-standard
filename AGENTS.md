# Работа со стандартом фронтенда

- Пиши документы и отчёты по-русски.
- Сначала читай `README.md`, `standard/VERSION` и затронутую часть стандарта или skill.
- Требования находятся только в `standard/`. В skill и pipeline размещай порядок действий и ссылки, не дублируй полную спецификацию.
- Сохраняй различие обязательных требований, рекомендаций и примеров. Альтернативная библиотека сама по себе не является нарушением.
- Механизм тем обязателен с начала разработки. Конкретные темы, пресеты, шрифты и переключатели определяет продукт.
- Не привноси пути конкретной машины, приватные пакеты, серверы или обязательные инструменты вроде `rtk` в переносимые требования.
- Не добавляй кодогенератор, CI-framework, реестр идентификаторов и скрипты без повторяемой задачи, которую они действительно упрощают.
- Изменяя требование, проверь согласованность `standard/`, skill, pipeline и шаблонов. Изменяя упаковку, проверь оба способа использования skill: из этого репозитория и из установленной папки.
- Перед завершением проверяй UTF-8, Markdown-ссылки на локальные файлы, баланс code fences и `git diff --check`. Для skill используй валидатор целевого агента, если доступен; он проверяет формат, а не качество решений.
- Не объявляй поведенческую проверку skill выполненной, если проверены только Markdown и YAML. Не запускай аудиты/миграции других проектов без соответствующего поручения.
- Не редактируй автоматически принятые копии стандарта в прикладных проектах. Обновление их версии — отдельная задача.
- Сохраняй чужие изменения. Не перезаписывай существующий `AGENTS.md` проекта при подключении стандарта: добавляй согласованный блок.
- Не включай секреты, токены, частные данные и окружение разработки в коммиты.
- Публикуй коммиты и теги только в рамках разрешённой пользователем задачи; не перемещай опубликованные теги.
